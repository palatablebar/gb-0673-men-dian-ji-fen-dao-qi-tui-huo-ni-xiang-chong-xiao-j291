# 积分规则

会员号、事件号和消费引用均为字符串，前导零保留。积分必须正整数，使用Decimal校验后转为整数，不支持小数积分。事件时刻有时区偏移，统一UTC。规则有效窗与积分可用期均为半开区间。
同一时刻先发放，再消费，最后退款；同类按事件编号排序。消费批次按最早到期、最早发放、批次编号依次选择，余额不足时整笔失败。批次在到期时刻立即不可用，不能消费未来发放积分。
退款必须引用同一会员已成功消费，累计退款不得超过原消费。部分退款按原分配的逆序回拨，先回拨最后消耗的批次；未到期恢复，已到期只记过期退款，绝不复活。后续消费使用回拨后的可用余额。
发放积分=可用积分+已消费积分−全部已退款积分+自然到期积分+过期退款积分。已退款包括有效恢复与过期不恢复。失败消费与失败退款均不改余额，移入隔离。
期末时点默认2026-11-03T00:00:00+08:00，未来事件隔离。示例会员00001：100+80发放，消费120，退款30，其中20恢复、10过期；再消费50后剩余30。

# 积分转赠（M8）

裁决：提交即托管、领取才划转。一份积分在任一时刻只有一个可用主人；托管期间双方均不可用，不产生第二个可用主人。

- 事件只追加：`GRANT` 开户、`ESCROW` 提交冻结、`CLAIM` 领取划转、`REVOKE` 撤回原路退回、`EXPIRE` 托管到期核销。每条事件含 `seq/prev_hash/hash`，载荷哈希成链，篡改或覆盖历史在回放验链时直接报错。
- 状态机：待领取 →（接收方领取）已领取；待领取 →（转出方撤回）已撤回；待领取 →（任一批次过原到期日）已到期。已领取/已撤回/已到期为终结态，终结单上的重复操作返回 `ORDER_TERMINAL`，绝不重复记账。
- 冻结按 FEFO（最早到期批次优先）逐批分摊，转赠单 `lines` 逐行记录原批次号、积分数与原到期日；领取后新批次 `source_lot` 指向原批次，到期日不变；撤回按原批次逐批退回，到期承诺不变。
- 到期阻断：托管积分到达原批次到期日仍未领取，领取与撤回均被阻断，转 `EXPIRE` 核销，到期积分不复活（与自然到期守恒口径一致）。
- 幂等：`transfer_id` 即幂等键。同号同参数重试返回 `IDEMPOTENT_HIT` 且不新增事件、不新增额度；同号异参数返回 `IDEMPOTENT_CONFLICT` 拒绝。
- 乐观并发：提交事件时校验库内链尾哈希等于读取时链尾，不一致返回 409 `STALE_VERSION`，整笔不写入，旧版余额结果原样保留。
- 守恒：全系统 `sum(批次可用) + 待领取托管额 + 已核销到期额 = 累计发放额`；待领取、已领取、撤回后三种口径下双方可用额与批次到期依据可复核一致。
- 阻断原因码见 `app/modules/transfer/domain.py::BLOCK_REASONS`，主界面同屏展示状态、双方可用额与阻断原因。
- 边界：不做账户合并、不调整历史归属、不发放营销权益；转赠账本由对账后批次余额一次性种子导入（`SEED-` 前缀），导入幂等。
